# 261004-16 死なずに寝て復活とコード構成の相談

**相談日**: 2026年10月4日

## プロンプト本文

```text
もし、鳥が死にそうになったら、死ぬのではなく、その場で、寝てしまって、復活できるようにしてください
```

```text
今、 index.html　だけにコードを書いていますが、この仕組みのままでよいですか？以前、変更していたら、動かなくなってしまいました。バグがおきにくいように、おきても、簡単に修正できるように、良い方法を提案してください。
```

## 回答内容（または対応内容）

### 死なずに寝て復活

- おなか・ごきげん・げんきのどれかが0になっても死なず、その場で寝てしまう仕組みにした（お世話操作・時間経過の両方）。
- 寝ている鳥は世界で横に倒れ、目を閉じた絵になり、💤 と「ねむってる」ラベルを表示し、歩き回らない。
- 寝ている間はお世話ボタンと＋3時間を隠し、「🤲 なでて起こす」ボタンを表示する。3回なでると復活し、40未満の値は40まで回復する。
- 寝ている間は時間経過で値が減らず、空腹通知も出さない。
- ヘッドレスChromium（iPhone 13サイズ）で、寝る→3回なでて復活→再読み込み後も遊べることを確認した。
- 要件定義書の3.7を更新した。

### コード構成の提案（未実施・提案のみ）

- 現状の問題：約2万文字のHTML/CSS/JSが1ファイル・ほぼ1行に詰め込まれており、1文字の誤りでゲーム全体が止まり、どこが壊れたか見つけにくい。過去の「\n 混入による構文エラー」がこの典型。
- 提案1：ファイルを分ける（index.html / style.css / js/ 以下に 保存・鳥の絵・ゲームルール・画面表示・音 など役割ごと）。ビルド不要のまま GitHub Pages で動く。
- 提案2：普通の改行・インデントで書き直す（エラー時に行番号で場所が分かる）。
- 提案3：自動テスト（ブラウザで卵→孵化→お世話→寝る→復活 を自動プレイし、エラーが出たら失敗）。
- 提案4：GitHub Actions で push のたびに構文チェック＋自動テストを実行し、壊れたら公開前に気づけるようにする。
- 提案5：壊れたらすぐ戻せるよう、変更は小さく分けてコミットする（git revert で1つ前に戻せる）。
- 動作を変えずに作り替える作業なので、ユーザーの了承を得てから実施する。
