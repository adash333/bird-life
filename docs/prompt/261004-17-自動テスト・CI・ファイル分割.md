## 回答内容（または対応内容）

前回提案した順に、バグが起きにくく・直しやすい仕組みを入れた。遊び方は変えていない。

1. 自動テスト
   - `npm run check`：全JavaScriptの文法チェックと、index.html が読み込むファイルの存在チェック。
   - `tests/game.spec.js`：本物のブラウザ（Chromium）で、スマホ（iPhone 13）とPC（1280×720）の2サイズで自動プレイする15種類×2＝30件のテスト。卵が見える／3回あたためて孵化／お世話でゲージが変わる／3回のお世話で3時間進む／ヒナ→若鳥→成鳥で絵が変わる／産卵で家族が増える／0になると寝て3回なでると復活（お世話・時間経過の両方）／空腹通知／保存と再読み込み／壊れたセーブデータ4種でも止まらない／音ボタン、など。ページでJavaScriptエラーが1つでも出たら失敗する。
   - わざと構文エラーを入れる、寝る仕組みを死ぬ仕組みに戻す、などで壊すとテストが失敗することを確認した。
2. GitHub Actions
   - `.github/workflows/test.yml`：push のたびに `npm test` を自動実行する。
3. ファイル分割
   - `index.html`（骨組み）、`style.css`、`js/state.js`・`birds.js`・`birdArt.js`・`sound.js`・`save.js`・`rules.js`・`ui.js`・`main.js` に分けた。
   - ビルド不要・ファイルを直接開いても動くよう、通常の `<script src>` で順番に読み込む方式にした。
4. 改行して書き直し
   - Prettier で全ファイルを改行・インデントした（`npm run format`）。
   - エラーが起きたら画面に「⚠️ エラー: 内容（ファイル名 行番号）」を表示するようにした（Webサーバー上での表示を確認済み。ファイルを直接開いた場合はブラウザの制限で詳細が出ないため、コンソールを見るよう案内する）。
- README にファイル構成とテスト方法、要件定義書に技術方針・開発ルール、AGENTS.md に「push 前に npm test」「機能追加時はテストも追加」のルールを追加した。
