# 6歳の子どもとChatGPTで、ゼロから「たまごっち風ゲーム」を作ってみた【STEAM教育・前編】

※この記事は開発途中の記録です。今回は、ChatGPTと一緒にゲームをゼロから作り始め、機能をどんどん追加した結果、途中でゲームが動かなくなってしまったところまでを書いています。その後はClaude Codeに引き継いで修正を進めています。続きは後日追記する予定です。

## 6歳の子どもに「AIと一緒にプログラミング」を体験してもらう

6歳の子どもに、STEAM教育のひとつとしてプログラミングを体験してもらうことにしました。

これまでもMinecraftのModをAIに作ってもらうことはありました。ただ今回は、既存のゲームを改造するのではなく、**「何もないところから、自分で考えた新しいゲームを作る」**ことを目標にしました。

もちろん、6歳の子どもがJavaScriptを一から書くわけではありません。

子どもが「こんなゲームにしたい」「鳥を動かしたい」「音を出したい」「もっといろんな色の鳥がほしい」とChatGPTに話し、それをもとにAIにプログラムを書いてもらいます。

大人がコードを書くのではなく、子ども自身がゲームの仕様を考え、AIに言葉で伝え、出来上がったものを実際に触り、「ここを変えたい」と再び伝える。今回は、この繰り返しそのものをプログラミング体験として重視しました。

## ChatGPTは親のアカウントを使用

今回は6歳の子どもが対象です。

そのため、ChatGPTは子ども本人のアカウントではなく、**親のChatGPTアカウントを使用し、親が横で画面を見ている状態**で行いました。

子どもには、親の目の前でChatGPTに話しかけてもらい、その内容をもとにゲームを作っていきました。開発したプログラムは、親のGitHubアカウントに保存しています。

## 今回の開発環境

今回使った環境は以下です。

- PC：Panasonic CF-FC（2025年版）
- OS：Windows 10 Pro
- ChatGPT：Proプラン（月額200ドル）
- Windows版ChatGPTアプリ
- ChatGPTを親のGitHubアカウントに接続済み
- ソースコード：親のGitHubリポジトリに保存
- 公開：GitHub Pages

今回作ったゲームのリポジトリは bird-life です。GitHub Pagesを利用し、ブラウザからそのまま遊べるWebゲームとして作っていきました。

## 最初の一言は「たまごっちみたいなアプリを作りたいです。」

ChatGPTで新しいチャットを開き、最初に子どもが入力したのが、こちらでした。

> たまごっちみたいなアプリを作りたいです。

たったこれだけです。

最初から仕様書を作ったわけでも、画面設計を考えたわけでもありません。「たまごっちみたいなものを作りたい」というところからスタートしました。

するとChatGPTが、ごはん、遊ぶ、寝る、おなか、ごきげん、元気などを持つ、シンプルな育成ゲームの案を作ってくれました。

ここから子どもが実際に画面を見ながら、次々に注文を出していきます。

## 「次は違う鳥を育てたい」

次のアイデアは、

> もしゲームオーバーになったら、次の鳥は違う格好の違う模様の鳥を育てたい。

でした。

ゲームオーバーになったらすべて終わりではなく、次は違う鳥を育てたい。

そこで「鳥を育てる → ゲームオーバーになる → 新しい卵が登場する → 前とは違う鳥が生まれる → これまで育てた鳥は図鑑に残る」という方向に発展しました。

子どもからすると、「ゲームオーバー」という失敗も、次の鳥に出会うイベントになります。

## まずGitHubに保存する

ある程度方向性が見えてきたところで、途中の状態をGitHubに保存することにしました。

> とりあえず今の段階のGitHubに保存したいです。リポジトリ名は何がいいですか。

相談の結果、リポジトリ名は **bird-life** にしました。

GitHub Pagesで公開しやすいようPublicリポジトリにして、HTML、CSS、JavaScriptだけで動くシンプルな構成からスタートしました。

ゲームを作るだけでなく、「リポジトリとは何か」「GitHubに保存するとはどういうことか」「Webページとして公開するにはどうするのか」といった、ソフトウェア開発の周辺部分まで自然に体験できました。

## 「ゲームオーバー」ではなく、鳥が卵を産んで増えていくゲームへ

途中でゲームのコンセプトも変わりました。

> もし成長したら卵を産んで、どんどん増えていく仕組みにしてください。

そこで、単純な世代交代型から、**卵 → ヒナ → 若鳥 → 成鳥 → 産卵**という成長サイクルへ変更しました。

親鳥は消えません。成鳥が卵を産むと、新しい鳥が家族に加わります。つまり、1羽 → 2羽 → 3羽 → 4羽……と鳥の家族が増えていくゲームになりました。

さらに、親の特徴を子がある程度受け継ぎつつ、ときどき違う特徴が生まれる簡単な遺伝の仕組みも加えました。

## 卵は「あたためる」と孵化する

最初のバージョンでは、卵なのに「ごはん」「あそぶ」「ねる」が表示されていました。そこで、卵の間は通常のお世話ボタンを隠し、「あたためる」を表示し、3回あたためると孵化する流れにしました。

孵化後に「ごはん」「あそぶ」「ねる」が使えるようになります。このあたりから、単なるデモ画面ではなく、少しずつ「ゲーム」らしくなってきました。

## ブラウザを閉じても続きから遊べるようにする

次にlocalStorageを使い、ブラウザにゲームの状態を保存するようにしました。

これで、ページを閉じても鳥の家族、成長状態、おなか、ごきげん、元気などを引き継げます。サーバーやデータベースを用意せずに済むので、最初のMVPとしては非常にシンプルです。

## GitHub Pagesで実際に公開

GitHub Pagesを設定し、作ったゲームをブラウザで開けるようにしました。

最初は404が表示されましたが、Pagesの設定を確認して公開。自分がChatGPTに話して作ったゲームが、URLを開くと本当に動く。6歳の子どもにとっては、ここがかなり分かりやすい「完成した感」のある瞬間でした。

## 「音もほしい」

ゲームが動くと、次の要望が出てきます。

> 音ありにしてほしいです　鳴いている音や、食べさせてる、食べてる音とか、あと歩いてる音。

そこでWeb Audio APIを使って、鳴き声、食べる音、歩く音、孵化音、産卵音、睡眠音、卵をあたためる音を追加しました。

外部の音声ファイルを大量に用意するのではなく、ブラウザ内で簡単な効果音を生成する方式です。ただし、この「音」は後になって何度もトラブルの原因になります。

## 「Minecraftみたいに世界が見たい」

さらに子どもから、

> 世界が見たいです。マインクラフトみたいに。鳥に動いてほしいです。鳥に動いてほしいです。あと音がまだ聞こえません。

という要望が出ました。

最初はカードの中に鳥が表示されるだけの画面でしたが、ここで一気に方向転換。空、草原、木、池、花、巣などがある **Bird Life World** を作り、鳥がその中を自分で歩き回るようにしました。

Minecraftのような3D世界ではありませんが、まずは2Dの世界を用意し、その中で鳥が暮らしているように見せるMVPです。

## 「名前が同じ」「グラフに戻して」

実際に複数の鳥が生まれると、新しい問題が見えてきました。

> 名前が同じです変えてください。

そこで、そら、レモン、ミント、モモ、ルル……などの候補から、家族内で名前が重複しないよう自動命名する仕組みを追加。

また、

> ごちげんとお腹と元気をグラフに戻してください。

という要望も出ました。

一度、数値だけの表示に変わっていたステータスを、子ども自身が「前の方が分かりやすい」と判断したわけです。そこで、おなか・ごきげん・げんきを横棒ゲージに戻しました。

これは、実際に使う人が画面を見ながらUIを改善していく、ユーザーテストのような流れでした。

## 「何クリックかしたら自然に時間が経ってほしい」

次は、

> 何クリックかしたら自然に時間が経過するようにしてください。

という要望。

それまでは「＋3時間」というボタンを押さないと時間が進みませんでした。そこで、ごはん・あそぶ・ねるなどのお世話を3回すると、自動的にゲーム内時間が3時間進む仕組みにしました。

子どもはコードを書いてはいません。しかし、「この操作は不自然」「こうなった方がゲームっぽい」という感覚を言葉にし、ゲームのルールそのものを設計しています。

## 鳥の色と模様も増やす

続いて、

> いろんな鳥もいろんな色にしてください。模様も描いてください。

という注文。

絵文字だけでは鳥の個性を表現しにくかったため、SVGで鳥を描画する方式に変更しました。

体色、お腹の色、羽のアクセント色に加えて、無地、しま模様、水玉模様、ほっぺ模様、おなか模様などを追加。親の特徴を子がある程度受け継ぐようにもしました。

## 世界を画面いっぱいに。お腹が空いたら通知してほしい

さらに、

> 鳥の色が全部同じです。変えてください。あと、お腹が空いたとき、メールがえっと横から来るようにしてください。バツしないとなくならないことにしてください。あと、世界がスクリーン全部にしてください。

と、一度にかなり具体的なUIの注文が出てきました。

そこで、既存の鳥も個体ごとに色や模様を変える、おなかが減ったら右から通知を出す、×を押すまで通知を消さない、世界をブラウザいっぱいに表示する、お世話パネルを世界の上に重ねる、といった変更を加えました。

ここまで来ると、最初の「たまごっちみたいなアプリ」からはかなり大きく育っています。

## そして、ゲームが動かなくなった

機能をどんどん足していった結果、ついに問題が起きました。

画面には空や草原が表示されるのに、鳥がいない。ボタンを押しても動かない。

> なくなってしまいました。始められません。何とかしてください。

さらに、

> ベルを押しても音が出ません。また鳥がいないです。新しい鳥が一羽もいません。

そして、

> 始めるボタンを押しても何も変わりません。また、トリが一羽もいません。トリが死んじゃった時もちゃんと新しい卵が出てくるようにしてください。

と、実際に画面を触りながら不具合を報告していきました。

ChatGPT側でも、セーブデータの修復、全滅時の卵生成、JavaScriptの構文エラー修正などを繰り返しました。

最後には、

> 動きません。

という、非常にシンプルな報告に。

ここで、いったんChatGPTだけでの修正を止めることにしました。

## 「AIに作ってもらえば一瞬で完成」ではなかった

今回やってみて面白かったのは、AIを使ったからといって、ゲームが一直線に完成したわけではないことです。

むしろ、アイデアを言う → AIが実装する → 実際に触る → 気になるところを見つける → 変更を頼む → 新しい機能によって別の不具合が出る → 原因を調べる、という、普通のソフトウェア開発とかなり似た流れになりました。

6歳の子どもはJavaScriptの文法を知りません。

それでも、「こういうゲームにしたい」「これは変」「鳥が動いてほしい」「同じ名前は嫌」「ゲージの方が分かりやすい」「世界を画面いっぱいにしたい」と、次々に仕様を決めています。

AI時代のプログラミング教育では、コードを一字ずつ書けることだけでなく、**自分が作りたいものを考え、それを言葉で説明し、出来上がったものを評価し、修正点を伝える力**も重要になるのかもしれません。

## 次回：Claude Codeで修正へ

このあと、動かなくなったゲームをClaude Codeに引き継ぎ、コードを確認しながら修正してもらっています。

今回の記事は、あえて**「ChatGPTと子どもだけでどこまで作れたか。そして、どこで壊れたか」**までで一区切りにします。
