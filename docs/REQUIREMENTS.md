# Bird Life 要件定義書

最終更新: 2026年10月10日（261010-02 時点）

この文書は `docs/prompt/` に保存されたユーザーの要望をもとに、Bird Life が満たすべき要件をまとめたものです。
**仕様を変更したときは、この文書も同じコミットで更新します。**（各要件の右に、根拠となったプロンプト記録の番号を記載）

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| 名称 | Bird Life |
| コンセプト | たまごっちのような鳥の育成ゲーム。卵から育てた鳥が大人になると卵を産み、家族がどんどん増えていく（01） |
| 対象端末 | スマートフォン・タブレット・PCのブラウザ（01, 09, 14） |
| 公開方法 | GitHub Pages（パブリックリポジトリ `adash333/bird-life`）https://adash333.github.io/bird-life/ （01, 02） |
| 技術方針 | ビルド不要・外部ライブラリなしの HTML / CSS / JavaScript。役割ごとにファイルを分ける（01, 17） |

## 2. ゲームの基本ループ

**🥚 卵 → 🐣 ヒナ → 🐤 若鳥 → 🐦 成鳥 → 🥚 卵を産む → 家族が増える → 次の世代を育てる**（01）

- 親は卵を産んだあとも群れに残り、親子が一緒に暮らす（01）
- 鳥はみんなメスで、大きくなると卵を産む（01）

## 3. 機能要件

### 3.1 卵と孵化（01, 12）

- 卵には「あたためる」ボタンだけを表示する
- 3回あたためると孵化してヒナになる（生後6時間から開始）
- 孵化時に個体名が付き、「たまごがかえりました！」と表示する

### 3.2 成長段階と見た目（01, 15, 20）

| 段階 | 条件 | 見た目 |
| --- | --- | --- |
| 卵 | あたため3回未満 | 🥚 |
| ヒナ | 生後18時間未満 | 割れた卵の殻に入った小さく丸い鳥。頭にふわ毛、大きな目、少し淡い体色 |
| 若鳥 | 生後18〜35時間 | 成鳥より小さい体、小さな羽1本、短いしっぽ |
| 成鳥 | 生後36時間以上 | 一番大きい体、3本の冠羽、長いしっぽ |

- ヒナ・若鳥・成鳥が**絵だけで簡単に見分けられる**こと（15）
- 世界に表示する鳥の縦横のサイズはヒナ32px・若鳥64px・成鳥128pxとし、成長段階が進むたびに約2倍の大きさになる（20）
- 世界の中の各鳥の足元に「卵／ヒナ／若鳥／成鳥」のラベルを段階別の色で表示する（15）

### 3.3 お世話とステータス（01, 06）

- 各鳥は「🍚 おなか」「❤️ ごきげん」「⚡ げんき」の3つの値（0〜100）を持つ
- 値は**横棒グラフ**＋数値で表示する（06）

| 操作 | 変化 |
| --- | --- |
| 🍚 ごはん | おなか +25、ごきげん +3 |
| 🧸 あそぶ | ごきげん +24、げんき −10、おなか −6 |
| 🌙 ねる | げんき +30、おなか −8 |
| ⏩ ＋3時間 | 年齢 +3時間、おなか −10、ごきげん −6、げんき −7 |

### 3.4 時間の経過（01, 07）

- 「＋3時間」ボタンで手動で時間を進められる
- お世話（ごはん・あそぶ・ねる）を3回すると、自然に3時間進む（07）
- あと何回のお世話で時間が進むかをメッセージで知らせる（07）
- 「＋3時間」を押すとお世話回数のカウントはリセットされる（07）

### 3.5 産卵と家族（01）

- 成鳥は時間経過後のおなか・ごきげん・げんきがすべて55以上なら、そのたびに卵を1個産む。1羽につき1回の制限はなく、お世話を続ければ繰り返し産卵する。以前に産卵した鳥も同じように産む（261010-01）
- 卵・寝ている鳥を含め、生きている家族が1000羽になったら、それ以上産卵しない。1000羽以上ある既存データも削除せず産卵を止める（261010-02）
- 生まれた卵は別の個体として群れに加わり、個別に選択して育てられる
- 産卵後は新しい卵が自動で選択される

### 3.6 個体差・遺伝（01, 05, 08, 09）

- 鳥ごとに**重複しない名前**を付ける（05）
- 体の色・おなかの色・アクセント色・模様（無地／しま／水玉／ほっぺ／おなか）を個体ごとに変える（08）
- 群れの鳥の色が全部同じにならないこと（既存セーブデータも含む）（09）
- 子は親の色・模様を一定確率で受け継ぎ、ときどき違う特徴になる（08）
- 新しく来る卵・生まれる鳥は、前の鳥とは違う格好・違う模様になりやすくする（01）

### 3.7 寝てしまう・復活とゲームの継続（10, 11, 12, 16）

- 鳥は**死なない**。おなか・ごきげん・げんきのいずれかが0になると、その場で寝てしまう（16）
  - 世界では横に倒れて目を閉じ、💤 と「ねむってる」ラベルを表示し、歩き回らない
  - 寝ている間はお世話ボタン・＋3時間は使えず、時間経過で値も減らない。空腹通知も出さない
  - 「🤲 なでて起こす」を3回押すと目をさまして復活する。復活時、40未満の値は40まで回復する
- 以前のバージョンで亡くなった鳥（セーブデータ上の死亡個体）は家族一覧に 🪶 の思い出として残す
- 生きている鳥が0羽になったら、**必ず新しい卵**を出してゲームを続けられるようにする（12）
- どんな状態でも「鳥が一羽もいない」「始められない」状態にならないこと（10, 11, 12）

### 3.8 世界（04, 09, 14）

- 空・草原・木・池・花・巣が見える「Bird Life World」を表示する（04）
- 世界は画面全体に表示し、パネルは世界の上に重ねる（09）
- 鳥は世界の中を自分で歩き回る（約2.6秒ごと）（04）
- 起きている成鳥は移動のたびに25%の確率で羽ばたきながら地平線より上の空へ飛び上がり、約1.8秒で着地する。画面サイズと地面での位置に合わせて飛行高度を調整し、足元のラベルも一緒に移動する。卵・ヒナ・若鳥・寝ている鳥は飛ばない（21, 23）
- 鳥をタップすると選択でき、鳴き声がする（04）
- 鳥・卵は**どの画面サイズでもパネルに隠れず見える**こと（14）
  - 幅900px未満（スマホ・タブレット）: お世話パネルは画面下、鳥はその上の地面を歩く。家族パネルは非表示
  - 幅900px以上（PC）: お世話パネルは左上、家族パネルは右上、鳥はその間の地面を歩く
- すべてのボタンが画面内に収まり、押せること（14）

### 3.9 家族一覧（01, 14）

- PCでは「🐦 鳥の家族」パネルに全個体を小さなアイコンと名前で表示し、押すと選択できる
- アイコンは小さいサイズ（44px）にそろえる（14）

### 3.10 空腹通知（09）

- おなかが35以下の鳥がいると、画面の右から通知がスライドして出てくる
- 通知は×ボタンを押すまで消えない
- ごはんをあげると、その鳥の通知は再び出るようになる

### 3.11 効果音（03, 04, 11, 12）

- Web Audio API で作る効果音（音声ファイルなし）: 鳴き声・食べる音・歩く音・孵化・産卵・ねる・あたためる
- スマホの制約に合わせ、「🔊 音をON」ボタンを押したときに音を開始する（04, 12）
- ボタンを押すとテスト音と鳴き声が鳴り、音が出ているか分かるようにする（11）
- 開始できなかった場合は「音を再試行」と表示する（11）

### 3.12 保存（01, 10, 11, 22）

- 「新しいゲーム」で現在のゲームを保存したまま、別の保存枠に卵1個のゲームを作る。「保存したゲーム」の一覧から切り替えて遊べる。各枠の群れ・選択・お世話回数などを独立して保存し、再読み込み後も選んだゲームを復元する。既存の単一セーブはゲーム1として引き継ぐ（261010-02）
- 保存枠はlocalStorage（`bird-life-games-v1`）に保存する。保存できない場合は新規作成を中止して通知し、現在のゲームを維持する。JSON入出力は選択中のゲームだけを対象とする（261010-02）

- 群れ・ステータス・選択中の鳥・位置を localStorage（`bird-life-save-v2`）に保存し、次回も続きから遊べる
- 古い形式や壊れたセーブデータを読み込んでもゲームが止まらないよう、値を補正して読み込む（11）
- お世話の回数（時間が進むまでの進捗）も保存・復元する（22）
- お世話パネルに「JSONエクスポート」「JSONインポート」を表示する。エクスポートは群れ・親子関係・名前・色と模様・成長・ステータス・睡眠と復活の状態・選択中の鳥・位置・お世話回数を含むJSONファイルをダウンロードする（22）
- インポートは選択したBird Life形式のJSONで現在のゲームデータを置き換え、自動保存する。置き換えについて操作欄に表示する（22）
- 不正なJSON・非対応形式・不正な鳥データはエラーメッセージを表示し、現在のゲームと保存データを変更しない（22）
- エクスポート・インポートは鳥のアイコン付きの丸いパステル色ボタンとする。エクスポート後は準備完了メッセージと「JSONを保存する」リンクを残し、自動ダウンロードが始まらない場合も保存できるようにする（24）
- CSSとJavaScriptの読み込みURLに版番号を付け、更新前のキャッシュによる機能の不一致を防ぐ（24）

## 4. 非機能要件

- ビルドや依存パッケージなしで `index.html` を開くだけで動く（01）
- コードは役割ごとのファイルに分け、改行・インデントして読みやすく書く（17）
  - `index.html`（画面の骨組み）/ `style.css`（見た目）/ `js/state.js`（共有状態）/ `js/birds.js`（鳥のデータ・成長）/ `js/birdArt.js`（鳥の絵）/ `js/sound.js`（効果音）/ `js/save.js`（保存）/ `js/rules.js`（ルール）/ `js/ui.js`（画面表示）/ `js/main.js`（ボタンと開始）
- エラーが起きたら、画面上にエラー内容とファイル名・行番号を表示する（17）
- JavaScript の構文エラーや初期化エラーで画面が止まらないこと。読み込み中は「ゲームを読み込み中…」を表示する（12, 13）
- 1羽の描画に失敗しても世界全体は止めない（11）
- スマートフォンで快適に遊べる画面構成にする（09, 14）

## 5. 開発・運用ルール

- 作業は `main` ブランチで行い、作業ごとに push する（AGENTS.md）
- 毎回の作業の最後に `/save-prompt` を実行し、ユーザーのプロンプトを一字一句そのまま `docs/prompt/` に保存する（01）
- **仕様が変わる作業では、この要件定義書も更新する**（15）
- push 前に `npm test`（文法チェック＋ブラウザでの自動プレイテスト、スマホ・PC両サイズ）を実行し、すべて成功させる（17）
- GitHub Actions が push のたびに同じテストを実行する。失敗したらすぐ直す（17）
- 新しい機能や仕様を追加したら、`tests/game.spec.js` にその動きを確かめるテストも追加する（17）
