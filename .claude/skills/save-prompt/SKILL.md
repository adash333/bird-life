# save-prompt — プロンプト原文と結果の記録・push

会話でのユーザーのプロンプトを**一字一句そのまま**保存し、その対応結果を Markdown で記録して、リポジトリの未コミット変更ごと main に push する。

## 最重要ルール：プロンプト原文を絶対に変更しない

`## プロンプト本文` に保存するユーザー入力は、会話に表示された原文をそのまま記録する。

- 要約しない
- 言い換えない
- 誤字・脱字を修正しない
- 表記ゆれを直さない
- 句読点を追加・削除・変更しない
- 全角・半角を変更しない
- 大文字・小文字を変更しない
- スペースを追加・削除しない
- 改行を意図的に変更しない
- Markdownとして読みやすくするための整形をしない
- URLを別表記に置換しない
- 長文でも省略しない
- 外部文書や貼り付け文章であっても省略しない
- 「全文は別ファイル参照」などに置き換えない

つまり、**保存対象のユーザープロンプト文字列そのものには一切手を加えない。**

複数のユーザープロンプトがある場合は、各プロンプトを時系列順に、それぞれ独立した fenced code block に入れて保存する。fence は保存用コンテナであり、その内側の本文は変更しない。

## 手順

1. **ファイル名を決める**
   - 形式: `docs/prompt/YYMMDD-NN-題名.md`（例: `261004-01-初期MVP作成.md`）
   - `YYMMDD` は今日の日付（西暦下2桁）
   - `NN` はゼロ埋め連番。docs/prompt/ にある同日プレフィックスのファイルを数えて次の番号にする
   - 題名はその回の内容を表す短い日本語

2. **ファイル内容**

   ```markdown
   # YYMMDD-NN 題名

   **相談日**: YYYY年M月D日

   ## プロンプト本文

   ```text
   （ユーザー入力を一字一句そのまま）
   ```

   ```text
   （次のユーザー入力を一字一句そのまま）
   ```

   ## 回答内容（または対応内容）

   - 何をしたか・何が分かったか
   - 重要な決定や仕様

   ## 反映済みアクション（あれば）

   - 作成・変更したファイルやコミット

   ## 情報源（外部参照があれば）

   - URL や文献（なければ「なし」）

   ## 関連ファイル

   - 関係するリポジトリ内ファイルへの相対リンク
   ```

3. **保存前チェック**
   - 会話上のユーザープロンプトと保存予定本文を文字単位で照合する
   - 内容を「改善」しない
   - 保存対象プロンプトの一部が取得できない場合は、推測や再構成をせず、その事実を報告する

4. **コミットして main に push**
   - 現在のリポジトリの全変更を対象にする
   - コミットメッセージ: `prompt: 題名 (YYMMDD-NN)`
   - ブランチは切らず main に直接コミット・pushする
   - 作業の最後は push 済みの状態で終える

## 注意

- **プロンプト原文の完全保存がこのスキルの最優先事項。**
- 回答内容・対応内容の部分は要約してよい。
- プロンプト本文だけは、読みやすさより原文忠実性を優先する。
- 記録は事実ベースで書き、未確定・未検証事項はそのように明記する。
- docs/prompt/ は作業ログなので YAML メタデータは不要。
